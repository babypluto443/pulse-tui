## 一、这一阶段做了什么（一句话版）

差异化卖点落地：压测进行中，终端实时显示瞬时 RPS、错误率和延迟曲线（▁▂▃▄▅▆▇█ sparkline）；一按 q，排水出报告、常驻屏幕等你看完再退。项目的核心并发架构第一次"看得见"了。

## 二、grill-me 定案的 4 个决策

| # | 决策 | 一句话理由 |
|---|---|---|
| 1 | 引擎整体放后台 goroutine，`tea.Tick` 250ms 直接拉 `agg.Snapshot()` | TUI 是消费者不是参与者；P3 的 Snapshot 已是并发安全深拷贝，PLAN 说的"加带锁 snapshot 口"其实早就有了 |
| 2 | **键盘桥接 cancel**（本阶段最重要的认知） | raw mode 关闭 ISIG：**Ctrl-C 不再产生 SIGINT**，`signal.NotifyContext` 在 TUI 下是聋的；model 持 cancel 函数，q/ctrl+c 触发与 -json 路径完全相同的排水 |
| 3 | 报告常驻，等 q/esc/ctrl+c 退出 | 报告给人看需要阅读时间；stdout 保持干净 |
| 4 | sparkline 手画八级块字符，不直接 import lipgloss；瞬时 RPS 由 TUI 侧差分 | SPEC §2"除 Bubble Tea 外无第三方依赖"红线：间接依赖 ≠ 直接依赖；metrics 保持纯净 |

## 三、逐文件详解

### 1. `internal/tui/tui.go` —— Model/Update/View 三件套

**关键设计 ①：Ctrl-C 的 raw mode 陷阱（本阶段最大的认知升级）**

终端在 raw mode（`term.MakeRaw`）下 **ISIG 被关闭**——Ctrl-C 不再由终端驱动转成 SIGINT 信号，而是作为普通字节（0x03）到达程序。这意味着：
- TUI 活着时，`signal.NotifyContext` 永远等不到 SIGINT
- **TUI 自己就是排水的唯一入口**：`tea.KeyCtrlC` / `q` → `m.cancel()` → 引擎走 P2 建立的排水路径 → 完成后 `DoneMsg` 送达 → 切报告视图
- 排水语义（停发射 → 在途跑完 → 报告）一字未改，只是信号的入口多了一个键盘事件——这正是 PLAN 风险表"信号仍由引擎层 ctx 管理，TUI 只消费"的落地形态

**关键设计 ②：瞬时 RPS 用差分，不污染 metrics**

`instantRPS(prev, cur) = (cur.Total − prev.Total) / (cur.Duration − prev.Duration)`——纯函数，首帧退化用累计口径，窗口零增长（排水期）防除零沿用累计值。实时性数据是**视图层**的职责，聚合器一个字段都没加。

**关键设计 ③：报告复用不重写**

`DoneMsg` 到达时，`report.Text(final, &buf)` 渲染成字符串存进 model——PLAN"复用 report 包，别写第二遍"落地。P3 埋的"双轨同源"在 P4 兑现成第三轨（TUI 内的报告 = 文本报告）。

**基础概念**：`tea.Tick(interval, fn)` 返回一个 Cmd，消息处理完再发下一个 tick——**时钟是链式的**，不是后台死循环。忘掉续 tick 的结果就是画面冻在第一帧。

### 2. `internal/tui/sparkline.go` —— 手画曲线

`▁▂▃▄▅▆▇█` 八级块字符，0 基标度（latency 没有负值，从 0 起才能看出增长），超宽截尾保最新。纯函数 6 个断言全覆盖。

### 3. `cmd/pulse-tui/main.go` —— 三路分派

`-json` → 纯 JSON（管道）；`isTTY(stdout)` → TUI（AltScreen，退出自动恢复终端）；其余 → 文本降级（管道友好）。聚合循环移入引擎 goroutine，收工时 `p.Send(DoneMsg{...})` 通知 TUI。**stdout/stderr 的分工在 P3 立过契约，TUI 的启用条件（isTTY）是它的自然延伸**。

## 四、本阶段的设计哲学（浓缩版）

1. **依赖红线是靠"不 import"守的，不是靠 go.sum**：lipgloss 早已在 go.sum（bubbletea 的传递依赖），但我们一行都没 import——"唯一依赖"的承诺才立得住。
2. **对环境的假设要拆开验证**："Ctrl-C = SIGINT"这个 30 年的肌肉记忆在 raw mode 下是错的；M4 验收必须复测 Ctrl-C 正是 PLAN 预判了这类环境差异。
3. **TUI 是视图不是引擎**：所有"聪明"（排水、聚合、口径）都在引擎层，TUI 只会拉快照、差分、画字符——所以它可以随时死掉而不伤害数据。

## 五、踩坑记录

| 坑 | 现象 | 根因 | 解法 |
|---|---|---|---|
| ① sparkline 画出碎字节 | 输出 `"\xe2\xe2\xe2"` | 块字符是 3 字节 UTF-8，`WriteByte(blocks[idx])` 取的是**单字节** | `[]rune(blocks)` + `WriteRune`（单字节思维写 UTF-8 是新手经典坑） |
| ② 零增长用例红 | instantRPS 得 100 期望 50 | 测试复用了 Duration=500ms 的旧 prev，dt 并非 0 | 测试自己的夹具要按用例重造，别跨断言复用 |
| ③ 测试文件未用 import | 编译失败 | 重构测试时忘删 | — |
