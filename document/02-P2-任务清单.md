# pulse-tui · P2 任务清单（grill-me 细化版）

> 日期：2026-10-08 · 依据 PLAN P2 + SPEC §5/§6，经 grill-me 拷问会定案
> P1 交付的契约（必须履约）：signals 由调用方创建；rate.Run 是唯一 close 方；
> **worker 消费必须 select 监听 ctx.Done()，不能闷头 range**。

## 一、已锁定的设计决策（4+1 项）

| # | 决策点 | 结论 | 理由摘要 |
|---|---|---|---|
| 1 | API 形态 | 函数式 `Run(ctx, cfg Config, signals <-chan struct{}) <-chan Result` | 与 P1 风格一致；attack 是 Result 唯一生产方，WaitGroup 归零后 close Result 流，main 端 range 天然安全 |
| 2 | Result 字段 | `Timestamp`（完成时刻）/ `Latency`（写出→读完 body）/ `StatusCode`（无响应=0）/ `Error string`（只装传输层失败） | Result 只当原始记录员，2xx/4xx/5xx 分类裁判权在 P3；开始时刻由 Timestamp−Latency 推出，不冗余 |
| 3 | 排水语义 | **在途自然跑完**：请求挂内部 drain ctx（全部工人完工后才取消），Ctrl-C 只停发射不杀在途 | SPEC §6"等在途返回、前半段数据不浪费"；避免报告末尾出现人为错误尖峰；最坏排水 = `-timeout`，由用户旋钮兜底。PLAN"NewRequestWithContext 第二取消通道"的意图由 drain ctx + timeout 承担，**deviation 已记录** |
| 4 | burst 容量 | `= -c`（工人池大小），signals channel 由 main 创建 | 排队上界 = 2c；背压响应快；语义可解释（"背压阈值就是工人池大小"） |
| 5 | Transport（无需拷问，直接定） | `MaxIdleConnsPerHost = MaxConnsPerHost = c`；自定义 Transport 不 ForceAttemptHTTP2（统一 HTTP/1.1）；重定向走 stdlib 默认跟随 | worker 池已限在途 ≤ c，连接层同上限是防御性对齐；否则高 RPS 下 TIME_WAIT 拖慢实测 |

**Config 定稿字段**：
```go
type Config struct {
    URL     string            // 目标 URL
    Method  string            // 空 → GET（main 已规整大写，这里兜底）
    Header  map[string]string // 自定义 header
    Body    []byte            // 请求 body
    Timeout time.Duration     // 单请求超时（挂到 http.Client.Timeout）
    Workers int               // 工人池大小（-c）
}
```

## 二、任务清单

| 编号 | 任务 | 要点 | 完成标志 |
|---|---|---|---|
| T2.1 | `internal/attack/attack.go`：Result + Config + Run | ① Run 内部：校验 → 构建 http.Client（Transport 按 #5 调参，Client.Timeout = cfg.Timeout）→ drain ctx → N 个 worker goroutine → `go func(){ wg.Wait(); cancel(); close(results) }()` → 返回 results ② 参数校验：URL 空 / Workers ≤ 0 / Timeout ≤ 0 → 直接 close results 并返回错误流？——**定案：panic 不行、返回预关闭的 results + error 怎么传？** 用 `Run` 返回 `(<-chan Result, error)` 双返回值，校验失败返回 nil, err | 签名定稿，闭环 |
| T2.2 | worker 循环与单请求 | ① 两级 select：先非阻塞查 `ctx.Done()`（优先级，取消后绝不处理遗留号）再收 signals ② `http.NewRequestWithContext(drainCtx, ...)`；body 用 `bytes.NewReader` 每次新建（Reader 有游标，复用会从上次位置读）③ `io.Copy(io.Discard, resp.Body)` + `Close`——不读完 body 连接不能复用 ④ latency：Do 前 `time.Now()`，读完 body 再 `time.Since` | 单请求全口径正确 |
| T2.3 | `attack_test.go`（httptest） | ① `TestRateAccuracy`：rate=100、2s、瞬时 200 端点 → 完成数 200±5%（M2 验收的短跑版）② `TestDrainOnCancel`：300ms 慢端点，中途 cancel → 在途请求**完成入账**（非 error）、发射停止、程序不悬挂 ③ `TestWorkerBounded`：慢端点 + 原子计数器测峰值并发 ≤ c ④ `TestResultFields`：POST + header + body 回显 → 各字段正确 | `go test ./internal/attack/` 全绿 |
| T2.4 | main.go 接线 | `signal.NotifyContext` → signals `make(chan struct{}, c)` → `go rate.Run(...)` → `attack.Run` → `range results` 计 total → 打印占位报告（total + 墙钟耗时 + 粗算 RPS） | 闭环可跑，Ctrl-C 排水 |
| T2.5 | 工程检查 | `gofmt -l` / `go vet` / `go build ./...` | 三项全过 |
| T2.6 | M2 验收（原文） | ① 本地 `python3 -m http.server`（ThreadingHTTPServer），`./pulse-tui -r 100 -d 10s http://127.0.0.1:8123/` → 实测 RPS 100±5% ② 压测中途 `kill -INT` → 程序不悬挂、照常出报告 | M2 达成 |

## 三、明确不做（防膨胀）

- ❌ 不做 `-burst` 独立 flag（v2）
- ❌ 不做二段式排水（第一次优雅/第二次强杀）
- ❌ 不做 httptrace 分段耗时（SPEC §2 非目标）
- ❌ Result 不加 Bytes 字段
