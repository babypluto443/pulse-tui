> 阶段目标：陌生人一行 `go install` 可用；README 自解释。

## 一、已锁定的设计决策（4 项）

| # | 决策点 | 结论 | 理由摘要 |
|---|---|---|---|
| 1 | git 策略 | AI 负责 `git init`、`.gitignore` 完善、initial commit、`tag v0.1.0`；**GitHub 建仓 / push / release 由用户在终端完成**（AI 给逐条命令） | 账号与授权在用户侧；push 后 go install 链路即通 |
| 2 | README 语言 | `README.md` 英文为主体 + 底部一节中文简介，单文件 | 受众"全球开发者"（SPEC §1）；不拆双语文件，v0.1 不背双倍维护 |
| 3 | demo 形态 | 用 pty 脚本捕获 **TUI 真实渲染帧**贴代码块；GIF 标 TODO | 零额外工具、内容真实；vhs/asciinema 是锦上添花 |
| 4 | 首批压测对象 | **pluto_feed**（本地 docker MySQL :3308 + `go run ./cmd/server`），压 GET feed 接口 | 用户从 0 建的项目，服务最轻最熟；DiTing-Go 留第二批 |

## 二、任务清单

| 编号 | 任务 | 要点 | 完成标志 |
|---|---|---|---|
| T5.1 | `build.sh` 交叉编译脚本 | GOOS/GOARCH 矩阵：linux/darwin × amd64/arm64；产物出 `dist/`（tar.gz/zip 带版本号）；不引 goreleaser（守零依赖精神） | 四平台产物本地可构建 |
| T5.2 | pty 捕获 TUI demo 帧 | 复用 M4 验收脚本改造：起本地服务 → 跑 TUI 数秒 → 抓含 sparkline 的渲染帧 → 清洗成 README 代码块 | demo 内容 100% 真实 |
| T5.3 | `README.md` | 英文主体：一句话定位 / install & build / flags 表 / demo / 与 hey-vegeta-k6 定位对比（复用 SPEC §1 叙事）/ 非目标摘要 / license 占位；底部中文简介节 | 自解释 |
| T5.4 | git 收尾 | `git init` → initial commit（含 .gitignore 补 dist/）→ `tag v0.1.0`；产出**给用户的 push 命令清单**（gh repo create / git remote add / push -tags） | 本地仓库就绪，待用户 push |
| T5.5 | pluto_feed 真实压测 | docker 起 MySQL → `go run ./cmd/server` → 探活 → `pulse-tui -r 100 -d 10s` 压 feed 接口 → 数字进 README（Run against your own services 节） | 真实战果一份 |
| T5.6 | go install 验证 | 本地：`go install ./cmd/pulse-tui` → `~/go/bin/pulse-tui -h` 可跑；远程：给出 push 后的验证命令 | 链路就绪 |
| T5.7 | M5 验收核对 + 开发记录 | 对照 M5 原文逐项核对；`document/09-P5-开发记录.md` + 项目总收官摘要 | 归档 |
