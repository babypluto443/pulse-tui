**基础概念**：
- **`cmd/<名字>/`** 是 Go 社区惯例：放"能编译成可执行文件"的入口包。名字就是装好后的命令名。
- **`internal/`** 是 Go 的特殊目录：别的项目 import 不了里面的包，强制把实现细节锁在自己项目内。
- 空包靠 `doc.go` 占位——只写包注释不写代码，让 `go build ./...` 能整体编译，同时把"这个包将来干什么"钉死在注释里。

## 三、逐文件详解

### 1. `cmd/pulse-tui/main.go` —— CLI 骨架（本阶段唯一实体代码）

**做什么**：三步走——`parseFlags()` 解析参数 → `validate()` 拒绝脏参数 → 打印"参数确认"回显。没有任何网络请求。

**关键设计 ①：`-H` 为什么要自定义类型**

stdlib `flag` 只认识"一个 flag 一个值"，`-H` 重复出现会被后者覆盖。解法是实现 `flag.Value` 接口（两个方法：`String() string` 和 `Set(string) error`），再用 `flag.Var()` 注册：

```go
type headerList []string

func (h *headerList) Set(v string) error {
    *h = append(*h, v)   // 每次 -H 出现就追加，不覆盖
    return nil
}
```

**基础概念**：`flag.Var` 拿到的是接口——只要类型实现了 `Set`/`String` 两个方法，flag 包就知道怎么往里塞值。这就是 Go 的"小接口"哲学：不搞继承，凑齐方法签名就算数。

**关键设计 ②：`-r` 用 `float64`（本阶段唯一一次改 spec）**

SPEC 原文把 `-r` 的类型列写成 `duration`，但语义是"每秒发射请求数"、默认 50、M1 验收是"rate=100 → 间隔 10ms"。如果真用 `flag.Duration`，`-r 100` 会解析成 **100 纳秒**，和验收标准完全对不上。已和作者确认：改为 `float64`，好处是天然支持 `0.5` 这种亚赫兹速率（一分钟一个请求也压得出来），且 P1 的发号公式 `start + n/rate` 直接可用。SPEC/PLAN 已同步订正。

**关键设计 ③：`validate` 用指针接收者**

```go
func (c *config) validate()
```

函数内部要做 `c.method = strings.ToUpper(c.method)`（把 `-X post` 规整成 `POST`）。Go 里方法接收者分值/指针两种：**值接收者拿到的是副本，改了也白改**；要改到原值上必须用指针接收者。这是新手高频坑，第一版就踩了，`gofmt` 不报但逻辑不生效，靠自己排查改掉的。

**关键设计 ④：边界在 P0 就守住**

`-r 0` 会让 P1 的 `n/rate` 除零、`-d 0` 会让压测瞬间结束、URL 缺失则什么都干不了。这些校验放在 `validate()` 统一做，不合法直接 `os.Exit(2)`——**让错误在入口死掉，别流进后续阶段**（fail-fast，和 pluto_feed 里"密钥不能有默认值"同一个思想）。P1/P2 接管时拿到的参数保证是干净的。

**基础概念**：`flag.Parse()` 之后，非 flag 的位置参数（这里的 URL）从 `flag.Arg(0)` 取。这要求 URL 写在最后：`pulse-tui -r 100 http://x`，不能写在 flags 前面。

## 四、本阶段的设计哲学（浓缩版）

1. **先立契约，再写实现**：四个包的 `doc.go` 把职责、核心思想、坑点提前写死（比如 rate 的"绝对时间表"、attack 的"Result 字段一次定好"），后续阶段照契约填代码，不会写歪。
2. **入口即闸门**：参数校验和规整（大小写、必填、正负）全在 main 收口，下游永远拿干净数据。
3. **文档即事实**：发现 SPEC 自相矛盾时不是硬写，而是先问作者拍板，再同步改 SPEC + PLAN——"改需求先改文档"这条纪律从 P0 开始执行。

## 五、踩坑记录

| 坑 | 现象 | 解法 |
|---|---|---|
| SPEC 的 `-r` 类型列写 `duration` | `-r 100` 若按 duration 解析 = 100ns，与 M1 验收矛盾 | 确认后改 `float64`，SPEC/PLAN 同步订正 |
| `validate` 用值接收者 | `strings.ToUpper(c.method)` 改在副本上，`-X post` 回显仍是小写 | 改指针接收者 `*config` |
| `gofmt -l` 列出 main.go | 结构体字段对齐、缩进不合规范 | `gofmt -w` 统一格式化（Go 项目提交前必跑） |
